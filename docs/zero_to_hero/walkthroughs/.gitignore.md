`.gitignore` lists paths that **Git must pretend do not exist**. It never offers them for committing, and `git status` never mentions them. Three kinds of things belong here (§4.1): **secrets**, **things rebuilt automatically**, and **large or licence-restricted data**.

Pattern rules:

- `#` starts a comment;
- a trailing `/` means "a folder with this name, anywhere";
- `*` matches any characters;
- `[abc]` matches one of the listed characters;
- a leading `!` makes an exception — "don't ignore this one after all".

@@ 27
`.env` — files holding passwords and keys. **A secret committed once stays in Git's history forever**, even if the file is deleted later. This line is the first defence.

@@ 28

@@ 29
`!.env.example` — the exception. Example files contain **no** secrets, only placeholder values, and they *must* be committed so people know which settings exist.

@@ 30
`!.env.example.*` — a second exception, for files whose names merely *start* with `.env.example`: the book's walkthrough `.env.example.md` and its snapshot `.env.example.snap`. !!! real "Real world — a trap found by reading carefully"
    Nobody noticed this hazard by running the code. It was found while *writing the explanation* of line 28. Explaining every line is not only for the reader: it is also one of the most effective ways to review code.
