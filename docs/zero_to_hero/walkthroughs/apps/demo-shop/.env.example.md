An **example settings file** for the demo shop. The shop reads six environment variables (`lib/config.ts`); this file lists them all with explanations, to copy into `apps/demo-shop/.env.local`, which Next.js loads automatically. The real `.env.local` holds a secret key and a secret, so Git ignores it (`.gitignore`: `.env.*`); only this harmless example is committed.

!!! warn "Careful — placeholders that fail safely"
    Every placeholder here is chosen to **fail**, never to half-work. The key `dk_test_REPLACE_ME` is too short for the SDK to accept; `SHOP_SECRET` is empty, which the shop refuses at start-up. A first version used a long placeholder secret — long enough to be *accepted*. Anyone who copied the file without editing it would have run a shop whose pass cookies anybody could forge, using the secret published right here.

`DWARPAL_API_URL` — where the Dwarpal API is.

@@ 5
`DWARPAL_ISSUER` — the issuer name the API writes into its tokens (`iss`). In development it is the same address; in production the two may differ, for example if the shop reaches the API through an internal address.

Where the next two values come from: the `seed-dev` command (§5.1.3).

@@ 8
`DWARPAL_PROJECT_ID` — the shop's project ID, which every token for the shop must name as its audience.

@@ 9
`DWARPAL_API_KEY` — the shop's secret test key.

@@ 11-12
How to make a good secret: Python's `secrets` module, 32 random bytes as URL-safe text.

@@ 13
`SHOP_URL` — the shop's own public address, used to build its return address and its redirects.

@@ 14
`SHOP_SECRET` — the secret the shop signs its "age checked" cookie with (`lib/pass.ts`). Empty here on purpose.
