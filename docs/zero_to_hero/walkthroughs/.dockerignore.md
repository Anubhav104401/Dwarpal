**What stays out of every image's build** (Phase 8, §5.8.2): Docker's ignore list, so images get only what they need, and nothing private.

@@ 1-2
What this file is for: when Docker builds an image, it first packs up the folder it builds from — the *build context* — and this file lists what to leave out of that pack. Left out: installed dependencies and builds (each image makes its own, for its own system), local secrets, data, caches, and anything about this computer. The builds are smaller and faster, and nothing private can end up inside an image. The patterns work as in `.gitignore`: `**/` means "in any folder".

@@ 3-7
Installed packages and built files: Node's `node_modules`, Next.js's `.next` builds, Python's virtual environments (`.venv`) and its compiled files (`__pycache__`, `.pyc`).

@@ 8-10
Secret settings — `.env`, and `.env.local` or any other `.env.` file — but not `.env.example`, which holds no secrets: the `!` brings back a file an earlier line left out.

@@ 11-13
Git's own history (`.git`), the assistant's notes (`.claude`) and the datasets (`.datasets`: faces, never to be copied anywhere they needn't be).

@@ 14-15
**`.tools`** (added 9 Nov) — desktop tools for making render data (decision D23), such as a portable Blender: more than a gigabyte that no image needs.

@@ 16-18
Training runs and their records (`.runs`, `mlruns`) and security scan results (`.scan`).

@@ 19-22
What browser tests leave behind: results, reports, Lighthouse's files and the e2e cache (the fake camera and the specimen passport).

@@ 23-25
The models: on the server they are mounted read-only from `/opt/dwarpal/models`, not built into an image — except the face landmarker, which the web app's build copies into its public files for browsers.

@@ 26
The built book: a large page that no image serves.
