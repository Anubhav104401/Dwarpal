# Glossary

Every technical word used in the book, in alphabetical order. The section in brackets is where the idea is first explained.

Age assurance
:   Any method of establishing someone's age with some level of confidence. The umbrella term for verification, estimation and inference. (§1.5)

Age estimation
:   Guessing age from a physical characteristic, usually the face. Fast and private, but it always carries some error. (§1.5)

Age inference
:   Deducing age from other facts, such as holding a credit card. (§1.5)

Age verification
:   Establishing age from an authoritative source, such as an ID document or a digital-ID app. (§1.5)

API
:   *Application Programming Interface.* A menu of requests one program offers to other programs. Each request it accepts is an **endpoint**. (§0.11)

Argument
:   A value handed to a function or a command. In `python build.py --strict`, `--strict` is an argument. (Part X)

Arm
:   A family of processor designs, used in phones and in Oracle's free Ampere servers. A program built for one family (Arm, or the x86 of most laptops) doesn't run on the other without slow emulation, so Dwarpal's images are built on Arm machines. (§5.8.1)

Audit log
:   A permanent, ordered record of important events (who changed what, when). Ours is *tamper-evident*: each entry includes a fingerprint of the previous one. (§3.3)

Backend
:   The programs that run on servers, out of the user's sight. (§0.10)

Biometric data
:   Information about a person's body, such as their face. (§1.11)

Bit, byte
:   A bit is a single 0 or 1. A byte is 8 bits, enough for a number from 0 to 255. (§0.1)

Buffer / challenge age
:   An extra margin above the legal age. For example, "pass only if the estimate is 25 or more, for a legal age of 18". (§1.8)

Canvas
:   A drawing surface a web page keeps in memory. Code can draw on it — a frame of video, say — and save the result as an image file. (§5.6.5)

Certificate
:   A digital document, signed by a trusted organisation, proving a server's identity for HTTPS. (§0.9)

Client
:   A program that asks a server for something — for example, a web browser. (§0.7)

Clopper–Pearson bound
:   A method for working out, from a test result like "6 out of 600", the worst plausible true rate at a chosen confidence level. (§3.3)

Code / source code
:   The human-readable instructions of a program, written in a programming language. (§0.3)

Commit
:   A saved snapshot of a project in Git, with a message explaining the change. (§0.15)

Compiler
:   A program that translates a whole program into machine code before it runs. (§0.4)

Container
:   A running copy of a Docker image. (§0.14)

Contract test
:   A test that checks an API against its published description: every answer must be one the description allows. Dwarpal's is generated by Schemathesis from the OpenAPI document. (§5.4.6)

Coverage
:   In this book: the share of a file's non-blank lines that have an explanation. (Part X)

Cron
:   A notation for repeating schedules, named after the Unix tool that runs them: five fields — minute, hour, day of the month, month, day of the week — where `*` means "every". `7,22,37,52 * * * *` is 7, 22, 37 and 52 minutes past every hour. (§5.8.5)

CSRF (cross-site request forgery)
:   Tricking someone's browser into sending a request to a site they are signed in to, from another site. Prevented by a secret token the other site can't read, and by checking the request's origin. (§5.4.5)

Database
:   A program that stores data permanently and answers questions about it quickly and safely. (§0.12)

Database role
:   A named identity inside a database server that holds rights: which tables it may read or change, and what else it may do. A connection works as one role at a time, and can switch to another it belongs to with `SET ROLE`. Dwarpal's API works as `dwarpal_app`, a role that owns no tables. (§5.4.1)

Dataclass
:   A Python shortcut for defining a class that mainly holds data. (Part X)

Deploy
:   To copy a program onto a server and start it there. (§0.13)

Dictionary (dict)
:   A Python collection of labelled values, looked up by key: `{"title": "Dwarpal"}`. (Part X)

DNS
:   *Domain Name System.* The internet's phone book, turning names into IP addresses. (§0.6)

DNS rebinding
:   Making a name point to one address when a server checks it and another a moment later, when the server connects — to steer its request inside its own network. Stopped by connecting to the very address that was checked. (§5.4.3)

Docker / image / volume
:   Docker packs a program with everything it needs into an **image**. A **volume** is a folder that survives when containers are thrown away. (§0.14)

Domain
:   A human-friendly internet name, such as `dwarpal.example`. (§0.13)

DuckDNS
:   A free service, run by volunteers, that gives out names under `duckdns.org` — such as `dwarpal-age.duckdns.org` — and answers every name under one (`api.`, `shop.`) with the same address. (§5.8.2)

Encoding
:   The agreement that maps characters to numbers. We always use UTF-8. (§0.2)

Endpoint
:   One specific request an API accepts, identified by a method and a path, such as `POST /v1/verification-sessions`. (§0.11)

Event
:   A record that something happened — such as a session completing — kept as it was at that moment, and never changed. Webhooks carry events. (§5.4.3)

Extension (file)
:   The letters after the last dot in a file name, such as `.py`, hinting at the kind of file. (§0.2)

Fail closed
:   When something goes wrong, the system chooses the *safe* answer ("retry" or "step-up"), never "pass". (§1.13)

False-adult rate
:   The share of children near the age limit whom the system wrongly lets through. Our most important safety number. (§1.7)

Fingerprint (hash)
:   A short code computed from a file's contents. Change one character and the fingerprint changes completely. (Part X)

Frontend
:   Everything that runs in the user's browser. (§0.10)

Function
:   A named, reusable block of code that takes inputs and gives back a result. (Part X)

Git, GitHub
:   Git records a project's history as commits. GitHub stores Git projects online. (§0.15)

GPU
:   *Graphics Processing Unit.* A chip that performs thousands of calculations at once — ideal for AI. (§0.1)

Hash chain
:   A list of records in which each record's hash also covers the previous record's hash, so changing or removing any record breaks every link after it. The audit log is one. (§5.4.4)

HMAC
:   A digest computed with a secret key, so that only someone holding the key can produce or check it. Webhook signatures are HMACs. (§5.4.2, §5.4.3)

Hosting
:   Renting computers in a data centre to run your website. (§0.13)

HSTS (HTTP Strict Transport Security)
:   A header telling browsers to use only HTTPS for a site, for a stated time, even when a link says `http://`. (§5.8.2)

HTML, CSS, JavaScript
:   The skeleton, the clothes and the muscles of a web page. (§0.10)

HTTP, HTTPS
:   The protocol browsers and servers use to talk. HTTPS is HTTP inside TLS encryption. (§0.8, §0.9)

Idempotency
:   The property of an operation that has the same effect however many times it is repeated. An `Idempotency-Key` makes "create a session" idempotent: a repeat gets the first answer. (§5.4.2)

Injection attack
:   Bypassing the camera completely, for example with software that pretends to be a camera. (§1.10)

Interpreter
:   A program that runs code by reading it line by line. (§0.4)

Introspection (of a token)
:   Asking the issuer whether a token is genuine and still valid, instead of checking its signature yourself. (§5.4.3)

IP address, port
:   An IP address identifies a computer on a network (the building). A port identifies one program on it (the flat). (§0.6)

JSON
:   A plain-text format for structured data, with six kinds of value. (§0.11)

Let's Encrypt
:   A free, automated certificate authority: it issues the certificates that make browsers trust a site's HTTPS, after checking that the site controls its name. Caddy asks it for them and renews them by itself. (§5.8.2)

Library / package
:   Code written by someone else that you can reuse. (§0.17)

Licence
:   The legal rules for what you may do with someone else's code, model or data. (§0.16)

Liveness
:   Evidence that a real, live person is in front of the camera at that moment. (§1.10)

localhost
:   A name that always means "this same computer". (§0.6)

Lockfile
:   An automatically generated list of the exact version of every library a project uses. (§0.17)

Lock-out back-off
:   Making each wrong password wait longer than the last: Dwarpal locks an account to the address the wrong tries came from, for a minute and then twice as long each time, at most an hour. (§5.4.5)

Markdown
:   A simple way of writing formatted text with symbols like `#` for headings and `**` for bold. This book is written in it. (Part X)

Media query
:   A question a page asks the browser about the device — whether its main pointer is precise (`(pointer: fine)`: a mouse or a trackpad), say, or whether the screen should be dark. (§5.6.5)

Method (HTTP)
:   The kind of action an HTTP request asks for: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`. (§0.8)

Model (AI)
:   A mathematical function with many adjustable numbers (parameters), tuned from examples so that it produces useful answers. (§1.6, Part 2)

Mojibake
:   Garbled text caused by reading a file with the wrong encoding. (§0.2)

Object URL
:   An address beginning `blob:` for data held in a page's memory — a photo just taken, say — so that an `<img>` can show it. It exists only in that page, and is handed back when no longer needed, freeing the memory. (§5.6.5)

OpenAPI
:   A standard, machine-readable way to describe an HTTP API: its operations, inputs and possible answers. Dwarpal publishes its own as `docs/api/openapi.json`. (§5.4.6)

Origin
:   A website's scheme, host and port together, such as `https://shop.example`. Browsers keep origins apart (the same-origin policy), and a Dwarpal project lists the origins its websites run on. (§4.13)

Outbox (transactional)
:   A table of messages waiting to be sent, written in the same transaction as the change they announce, then sent by a separate worker. (§5.4.3)

Pagination
:   Handing a long list over in pages. Dwarpal uses a cursor, "the items after this one", rather than an offset, "skip the first 40", so items added meanwhile can't make pages repeat. (§5.4.2)

Password hash
:   What is stored instead of a password: the output of a slow, salted one-way function such as Argon2id, which can check a password but never reveal it. (§5.4.5)

Pinning
:   Recording the exact version of a library, so the project builds identically everywhere. (§0.17)

Pixel
:   One dot of a digital image, stored as red, green and blue numbers. (§0.1)

Policy (row-level security)
:   A condition attached to a database table that decides which rows a role may see and change; the database adds it to every query by itself. (§5.4.1)

Presentation attack
:   Showing the camera something that isn't a live face: a photo, a screen, a mask. (§1.10)

Program
:   A set of instructions for a computer. (§0.3)

Protocol
:   An agreed set of rules for how messages are formatted and exchanged. (§0.8)

Proxy (attack)
:   An adult doing the age check on a child's behalf. (§1.10)

Public Suffix List
:   The list browsers use to tell where one site ends and the next begins. A name under a suffix on it — `duckdns.org` is one — counts as a site of its own, just like a bought domain. (§5.8.2)

Rate limit
:   A cap on how many requests a caller may make in a period of time; past it, the API answers `429` and says when to try again. (§5.4.2)

RBAC (role-based access control)
:   Giving permissions to roles, and roles to people, rather than permissions to each person. Dwarpal's roles are owner, admin, developer and analyst. (§5.4.5)

Regular expression (regex)
:   A tiny pattern language for finding text, such as "two @ signs followed by a number". (Part X)

Relying party
:   The website or app that relies on our age answer. (§3.3)

Request / response
:   One message from a client, and the server's reply. (§0.8)

Retention period
:   How long data is kept before it is deleted. Dwarpal keeps session metadata 90 days by default (1–365), then purges it; anonymous counts stay. (§5.4.4)

Risk budget
:   The maximum share of dangerous mistakes a policy accepts, for example "at most 2 % of 13–17-year-olds may pass". (§3.3)

Rotation (of a key)
:   Replacing a secret key with a new one, letting the old key work for a short grace period so that nothing breaks during the switch. (§5.4.2)

Row-level security (RLS)
:   A database feature that filters every query row by row through the table's policies, so that each tenant sees only its own rows, even if a query forgets to ask for that. (§5.4.1)

Scope (of a key)
:   One kind of operation an API key is allowed to perform, such as `sessions:read`. A key gets only the scopes its holder needs. (§5.4.2)

Security definer function
:   A database function that runs with the rights of its owner rather than of whoever calls it: a narrow, deliberate door past the usual rules. (§5.4.1)

Server
:   A program (or the computer running it) that waits for requests and answers them. (§0.7)

Shell / terminal
:   The window and program where you type commands. (§0.5)

Signed token
:   A small digital message sealed with a private key, so anyone with the public key can check that it is genuine and unchanged. (§3.3)

SNI (Server Name Indication)
:   The website's name, sent at the very start of a TLS connection, so a server that holds many websites presents the right certificate — which the client then checks is for that name. (§5.4.3)

SSRF (server-side request forgery)
:   Tricking a server into sending requests to places only it can reach, such as its own internal network. Webhook addresses are checked to prevent it. (§5.4.3)

Status code
:   The three-digit number at the start of an HTTP response: 2xx success, 4xx client error, 5xx server error. (§0.8)

Step-up
:   Moving to a stronger age-check method when the quick one is unsure. (§1.9)

Step-up conversion
:   Of the people sent to a stronger check, the share who finish it rather than leaving. Shown on the console's dashboard. (§5.5.2)

Table (database)
:   Rows (things) and columns (their properties), like a spreadsheet. (§0.12)

Template
:   A file with blanks (here written like `{{TITLE}}`) that a program fills in. (Part X)

Tenant
:   One customer of a shared system, whose data must stay separate from every other customer's. In Dwarpal a tenant is an organisation, or one of its projects. (§5.4.1)

TLS
:   *Transport Layer Security.* The encryption behind HTTPS. (§0.9)

Token bucket
:   A rate-limiting method: a bucket of tokens refills at a steady rate, and each request takes one, allowing short bursts but a limited average. (§5.4.2)

TOTP (time-based one-time password)
:   The six-digit code an authenticator app shows, changing every 30 seconds, computed from a shared secret and the time (RFC 6238). (§5.4.5)

Transaction
:   A group of database changes that either all happen or none happen. (§0.12)

UTF-8
:   The universal text encoding, able to store every character in every language. (§0.2)

Version
:   A label like `3.11.1` (*major.minor.patch*) identifying one release of a library. (§0.17)

Virtual environment (venv)
:   A private folder holding a specific Python and specific libraries for one project, so projects don't interfere with each other. (Part X)

Walkthrough
:   In this book: a file that explains another file line by line. (Part X)

Waterfall
:   Trying the quickest, most private age check first, and moving to stronger methods only when needed. (§1.9)

Webhook
:   A request a service sends to an address on your server when something happens, so you needn't keep asking. (§5.4.3)

X-Forwarded-For
:   A header that a reverse proxy such as Caddy adds to each request it passes on, saying which address the request really came from: the service behind the proxy sees only the proxy's own address. (§5.8.2)
